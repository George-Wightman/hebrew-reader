## What was done, and why it mattered

Fourteen commits. The three that changed the app most:

**The scheduler was lying (`df6f4fb`).** Measured against George's own backup: six days of
practice, 215 cards, and *hayom* — "today" — scheduled for **August 2027**. 129 of 298
records sat past 21 days on three or fewer answers. `srsApply` never checked whether a
review was due, and the session builder handed it the same word two or three times a
sitting. Both fixed; a Settings action corrects schedules already inflated.

**Grandad's voice was being thrown away (`fcf147d`).** `transcribeAudio` read the file,
sent it to Google, and let the audio fall out of scope — while the app separately spent
effort synthesising Hebrew badly. The blob is kept now, and a `note` card drills on it.
Side effect: listening practice no longer needs an installed Hebrew voice at all.

**It wasn't on a phone (`46b17e8`, then `61a007b`).** PWA, offline service worker, then
real sync. This is the change that altered how often the app gets opened.

Then four rounds of fixes from **real use on the Pixel**, which found things no amount of
desk testing would have:

- The mic listened and heard nothing. A held `getUserMedia` stream starved Android's
  recogniser — a `file://` workaround that outlived its problem and turned harmful.
- The word map couldn't be pinched at all; the Path couldn't be moved diagonally; the
  neural Android voice was being slowed with a constant tuned for a robotic Windows one.
- A pinch starting on a word box flung the box across the map.

**Two things were done deliberately differently from the audit**, both recorded in it: the
scheduler migration is an opt-in button rather than a silent on-open migration, and the
"honest ceiling" heuristic was dropped after measurement showed it caught nothing (`2.6^7`
is 803 days). Read F1 in the audit before revisiting either.

## What is left

The audit's own table is the source of truth. In priority order:

### Phase 4 — quota and storage *(next)*

**F8 — six features share a 20/day pool while a 500/day one idles.** Verified still true;
these call sites pass no model argument and so take the strong pool:

```
transcribeAudio · audioZoneBusy · learnMakeConversation
pathGenerateContent · learnTopUp · learnExplainWord · learnWhy
```

`learnExplainWord` and `learnWhy` are short teaching notes — exactly what `padAskExplain`
already sends to `GEMINI_MODELS_FAST`. Moving those two is a one-word change each and the
cheapest win left in the document. Transcription genuinely needs the strong model.

Worth adding alongside: a request ledger (same shape as `formsQAll`) so Settings can say
*"4 of your 20 strong-model requests used today"*. You cannot budget what you cannot see.

**F7 — form banks still grow inside `hvr_library`.** `formsSizeGuard` still only
`console.warn`s at 1MB, from one call site, in an app whose DevTools is never open. Move
`forms` to IndexedDB (`audioPut`/`audioGet` are the pattern) or at minimum surface the
warning in Settings.

### Phase 5 — the things that make it pleasant

- **F17 — no mistake review.** Highest-value cheap feature left. The end-of-session screen
  exists and the session object is still in memory at that point; add the missed cards and
  a "drill these now" button.
- **F18 — no dark mode.** Still zero `prefers-color-scheme` rules. The CSS is fully
  tokenised at `:root`, so this is one media block plus care that gold still reads as
  achievement on a dark ground. Matters more now the app is on a phone at night.
- **F11 — four divergent prefix tables.** `PREFIX1`, `PREFIX2`, `AI_PREFIXES`,
  `PAD_PREFIXES`. They disagree in ways with consequences; the clearest example of the
  "built bit by bit" seam.
- **F13 remainder — five dead functions** still present: `audioClearAll`, `convoAddScene`,
  `focusStar`, `openLibEditor`, `pendingCount`.

### Open questions, not yet decisions

- **F9 is not closed.** `GEMINI_TTS_MODELS` now leads with `gemini-3.1-flash-tts-preview`,
  which George's key can reach. **Nobody has confirmed whether real Hebrew audio actually
  works again.** Settings → Audio → *Build up audio library* is the test. If it works, the
  neural-audio feature has been dormant since 7 Aug for no reason.
- **F20 — three content systems** remains deliberately deferred. The Path still hasn't been
  walked start to finish; the right shared abstraction will be obvious after it has been,
  and guessed wrong before.
- **The mobile UI pass is half done.** `Export .xlsx` moved to Settings. Remaining
  candidates, none yet judged against real use: the lens row's three buttons eating toolbar
  width, and the Learn start screen's stats block pushing the Start button down the page.
  Ask George what actually feels wrong rather than guessing at 375px.

## Things built this cycle that the audit never mentioned

Because they didn't exist when it was written.

**Cross-device sync** — spec at `docs/superpowers/specs/2026-08-20-cross-device-sync-design.md`.
A private GitHub repo written through the Contents API; the file `sha` gives real conflict
detection. Merge is **field-aware**, not last-write-wins: per word *and per side* the more
recent answer wins, collections union, stats take the higher value per day.

Three properties are asserted by tests and must stay true — **commutative** (the answer
cannot depend on which device synced first), **idempotent** (syncing twice changes
nothing), and **lossless**. If you touch `mergeKeyMap` or anything it calls, those tests
are the contract.

Two accepted limitations, both deliberate and documented:
- **Stats undercount on a day practised on both devices** (10 + 5 reads as 10). Summing is
  correct once and then double-counts forever. Erring low is the honest direction.
- **Voice notes don't sync.** The audio blobs are megabytes in IndexedDB.

**PWA and offline** — `sw.js`, `manifest.webmanifest`, `icons/`, `index.html`. The worker is
stale-while-revalidate with a user-confirmed update, and **never reloads mid-session**.

**Settings reorganised** — was 21 rows and 813 words in four groups sorted by *risk*. Now
seven groups sorted by *subject*, with risk demoted to a per-row badge, a filter box, and
long rationale behind disclosures. The promise that every row states its effect before you
press it is intact; only the background moved.

## How to work on it

**Run it:** `.claude/launch.json` serves on **port 8778**. Tests are `?selftest=1`, and the
result lands on `window.__selftest` and in the page title.

**The one thing that will waste your time.** The service worker caches the app, so after
editing you will keep testing a stale copy and the test count will not move. Clear it
before every verification:

```js
for (const r of await navigator.serviceWorker.getRegistrations()) await r.unregister();
for (const n of await caches.keys()) await caches.delete(n);
location.reload(true);
```

This cost real time twice this cycle, once producing a "failing" test that had already been
fixed.

**Deploy:** `git push`. GitHub Pages serves `main` from root.

**Careful with:**
- **Heredocs and JS strings.** A Python heredoc turned `\n` inside a JS string into a real
  newline and broke the script. If the suite stops running entirely, suspect a syntax error
  and scan added lines for an odd quote count — `window.onerror` cannot report a parse
  error, because the handler never gets installed.
- **Temporal dead zone.** Several `const`s are declared far down the file. Anything running
  early — a service worker message, a boot timer — that touches `learnSession` or a key
  constant must be guarded; `typeof` throws on a TDZ `let`. `sessionBusy()` is the pattern.
- **His real data.** It lives on the `file://` origin *and* now the hosted one. There is a
  real backup at `Downloads/hebrew-reader-backup-2026-08-20.json` (52 keys, 241 words). The
  old isolated Chrome profile at `C:\HebrewLearningProfile` still holds the pre-web state.

**Device:** Pixel 7 Pro, Chrome, app installed to the home screen. Anything touch-, voice-
or permission-related can only really be confirmed there — say so rather than claiming a fix
works.

## The one habit worth keeping

Every significant bug this cycle was found by **measuring rather than reasoning**:

- The scheduler bug was theoretical until it was run against the real backup and produced
  *hayom → August 2027*.
- The sync merge looked correct until a test showed the output key order depended on
  argument order — two devices with identical data would have committed forever.
- The service-worker update path looked right until the suite reported 185 when it should
  have said 195.
- A stale click-suppression flag was found only because a test ran two gestures in a row.

The audit's F12 lesson was that the app's worst bugs lived in pure functions nobody tested.
That is still the lesson. 94 tests were added this cycle; coverage is better but uneven, and
the next person should keep writing the failing test first.
